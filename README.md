# Intransitive 練習室

[線上練習](https://tianyili.github.io/intransitive-practice/) · [GitHub](https://github.com/TianyiLi/intransitive-practice)

公開首頁預設簡單引擎，你執藍先手。可切換中等、困難或 Codex，並使用「戰役存取與復盤」。WebMCP 需要支援的瀏覽器；一般瀏覽器可以直接與本機計算的策略引擎對戰。

本機單頁遊戲，可與三種難度的策略引擎自動對戰，或與 Codex 透過 WebMCP 輪流對戰。無外部 AI API、帳號或金鑰。伺服器只公開白名單中的網頁資源。

啟動：`node server.mjs`，預設 `http://127.0.0.1:4318`。測試：`node --test engine.test.mjs strategy.test.mjs bot-controller.test.mjs records.test.mjs`。

## GitHub Pages 部署

需要 Node.js 22 以上，不需安裝套件。`npm test` 執行測試，`npm run build` 將 9 個公開資源複製至 `dist/`。`main` 每次 push 後由 GitHub Actions 測試並部署至 Pages；PR 只做測試與建置。所有模組與 Worker 採相對路徑，支援專案子目錄。

GitHub Pages 與本機是不同來源，瀏覽器不會自動搬移棋局。要延續本機存檔，先在原頁匯出 JSON，再到線上版匯入。棋局資料只存於使用者瀏覽器，不會上傳到 GitHub。

## 自動練習

開啟 `http://127.0.0.1:4318/?training=1`，預設你執藍先手、簡單引擎執紅。落子後引擎自動回應，不必到對話說「換你」。此網址採用獨立的分頁儲存鍵，保留原本 `/` 的 Codex 對局。

| 難度 | 決策 | 搜尋時間預算 |
| --- | --- | --- |
| 簡單 | 單步局面評估加入隨機變化，優先直接取勝與防止一步基地失守 | 通常數毫秒 |
| 中等 | 最多 3 手，另延伸 1 手交換檢查 | 650 ms |
| 困難 | 勝利條件導向，最多 5 手，另延伸最多 2 手基地威脅、防守或必要交換 | 1600 ms |

「手」是任一方的一次落子；深度依時間預算停止，頁面顯示實際完成深度。這些是搜尋配置，不是經過棋力評級的等級；沒有最佳走法保證。截止時間定期檢查，因此時間預算不是硬即時保證。

可隨時切換難度；新局可選先後手。引擎模式悔棋退回到自己的回合並暫停，重做同樣暫停；按「繼續」恢復自動回應。計算使用獨立 Web Worker，暫停、悔棋、新局與切換難度會終止舊計算；棋局 ID、版本及控制器世代會拒絕過期結果。重新整理保存棋局、對手和暫停狀態；最近一步的評估提示不保存。

引擎使用 Minimax、Alpha–Beta、迭代加深、走法排序和有限的威脅延伸。簡單與中等評分考量棋子數、保留剋制能力、受攻擊與回吃保護、活動空間及基地距離。

困難模式以三種實際勝利條件為主：進入基地、清空敵子、讓對方無合法走法。確定終局的分數遠高於所有局面估計；未達終局時，以依棋種區分的廣度搜尋估計通往基地的安全路線，排除友子阻擋、無法吃掉的敵子與受剋制的中途格，並比較雙方路程和敵方低活動度；一般棋子與交換評分降為 35% 的輔助項。路線假定其他棋子暫時不動，是搜尋末端的估計，並非必勝證明；對手回應由 Minimax 比較。延伸包含即將威脅基地的安靜走法及必要交換，不以連續吃子為目標。

重複局面只降低搜尋偏好，不增加三次重複和局規則。頁面走法文字是依落子特徵生成的提示，不是完整搜尋證明。

資料參考：[Berkeley CS188 Minimax / Alpha–Beta](https://inst.eecs.berkeley.edu/~cs188/textbook/games/minimax.html)、[CS188 迭代加深與限時搜尋講義](https://inst.eecs.berkeley.edu/~cs188/sp26/assets/lectures/cs188-sp26-lec07.pdf)。搜尋未找到可靠的 Intransitive 專用開局庫；本版評分為依遊戲規則設計的啟發式策略，不宣稱官方定式或影片策略。

## 與 Codex 對戰

預設玩家執藍（先手），Codex 執紅。點選棋子與合法目的地後，到 Codex 對話說「換你」。頁面不會在背景自動啟動 Codex；須在支援 WebMCP 的 Codex 瀏覽器使用同一分頁。棋局用 sessionStorage 保存於此分頁。悔棋、重做、新局、翻轉、棋譜匯出均可由介面操作。

## 戰役存取與復盤

點選「戰役存取與復盤」可以命名儲存目前戰役、選擇存檔、逐步查看唯讀棋盤、載入續下與匯出／匯入 JSON。存檔使用 localStorage，同一瀏覽器、同源分頁可讀取；上限 100 份，不會自動覆寫舊存檔。清除瀏覽器網站資料會刪除存檔，需要長期保留或跨裝置使用請匯出 JSON。

保存整條走法與目前游標，包含悔棋後仍可重做的部分；復盤時會標記重做分支。載入會先另存目前局為自動備份，再建立新 gameId 並暫停引擎，以防舊操作誤落子。存檔失敗則不載入。所有匯入走法都從初始局面逐步驗證，不信任檔案內聲稱的棋盤或勝負；兼容之前的 `intransitive-practice-v1` 匯出格式。匯入上限 1 MB、10,000 手。

復盤工具提供盤面與合法走法供 agent 分析，不會自動替棋局評分，也不會將復盤游標套用到當前對局。尚未另存的棋局仍只保存在該分頁的 sessionStorage。

## WebMCP

優先 `document.modelContext.registerTool`，兼容提供相同介面的 `navigator.modelContext`；不支援時如實顯示提示，不冒充已連線。八個工具：

- `get_game_state({})`：棋局 ID、版本、雙方顏色、盤面、回合、結果、棋譜及合法走法。
- `get_legal_moves({from?: "b4"})`：當前一方全部或指定棋子的合法走法。
- `play_move({gameId, expectedRevision, from, to})`：只在 Codex 模式替 Codex 落子；自動引擎模式拒絕操作，以免雙重落子。校驗棋局、版本、回合、座標與遊戲是否結束。操作使用與介面相同的規則引擎。
- `save_current_game({name?})`：另存目前完整戰役，回傳存檔 `id`。
- `list_saved_games({})`：列出存檔 `id`、名稱、雙方設定及步數。
- `get_game_record({recordId?})`：讀取完整棋譜與目前游標；省略 recordId 讀目前局，回傳的 `id: null` 表示未指向持久存檔。
- `get_review_position({recordId?, ply})`：讀取第 ply 手後的盤面、合法走法與前後步；0 是初始局面，不會改動對局。
- `load_saved_game({recordId, gameId, expectedRevision})`：先備份目前局，再載入指定戰役並暫停；須提供目前局版本。

Agent 復盤流程：先 `get_game_record` 固定目前步數，必要時 `save_current_game` 保存穩定快照，接著用存檔 id 呼叫 `get_review_position`。只為分析時不需呼叫載入工具。

只有成功的實際工具呼叫才顯示「Codex 已透過 WebMCP 連線」。此狀態代表此分頁已經成功收到工具呼叫，不代表 AI 常駐監聽。

## 規則來源與範圍

- https://meaf.us/rps2/ ，2026-09-16 公開前端 `assets/index-CNyk1zU_.js`：棋盤座標、初始配置、反對角線鏡像、八方向一步、R>S>P>R 吃子、基地、無棋子與無合法走法判負。初始藍方 R=b4,c3,d2；P=b5,c4,d3,e2；S=c5,d4,e3。
- 官方公開前端顯示線上選用的停滯和局上限 200 plies；本練習版採用連續 200 步無吃子和局，不計時、不實作線上評分、連線時限或約和。這不是官方伺服器判局行為的完整重製。
- 使用者影片 https://www.youtube.com/watch?v=LO_zcGNJriA ：已確認為 webgoatguy 的 I Reinvented Rock Paper Scissors。瀏覽器無法播放影片，字幕匯出回報無字幕；不宣稱已核對影片策略。頁面策略提示是基於棋規的通用練習提示。

21 項測試涵蓋配置、移動、九種吃子組合、終局、停滯、角色限制、棋局版本、悔棋與分支；搜尋引擎與規則引擎在 160 個種子局面的合法走法比對、雙方基地攻防、回吃陷阱、限時回退、輸入不變及取消過期工作；戰役存取往返、分支復盤、舊格式匯入、不合法棋譜與儲存失敗。困難模式另外驗證：放棄吃子選擇強制基地勝利、封鎖取勝，以及路線評估包含敵方控制。
